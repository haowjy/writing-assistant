# Test what changes when a writing brief leaves decisions open

Background agent p43 was asked to compare explicit and loose writing briefs, including whether the model asked questions or stated its assumptions. It completed the analysis and found that loose briefs produced substantially longer work, while all 40 loose attempts outside the alternatives family silently chose their own defaults.

The `custom50` suite contains 50 writing tasks. An “attempt” is one run of a task. The two comparison groups, called arms in the source, use different model-weight formats: `nf4` is a 4-bit quantized format, and `bf16` is a 16-bit brain-floating-point format. Quantization stores weights at reduced precision. Explicit briefs state more requirements; loose briefs leave more creative choices open.

Task identifiers combine a family and a case number, as in F2-02. F1 asks for a reply scene; F2 asks for local revision or exploration followed by writing; F3 asks for alternatives; F4 asks for construction or updating of a knowledge base (KB), the project reference files; and F5 asks for writing using retrieved project facts.

## What the comparison can show

Explicit briefs specified a 120–220-word target in 20/25 cases and a point of view in 15/25; loose briefs specified each in 0/25. Point of view, abbreviated POV in the source, determines whose perspective tells the scene. Loose briefs still named the deliverable in 12/25 cases. The comparison therefore mainly varies length, viewpoint and scope requirements rather than whether a file is requested. The analysis flags unequal mixes of conditions within F2, F3, F4 and F5, as well as the 12/25 loose briefs that name paths.

Loose deliverables were about 1.7 times longer. Mean word counts were 399 versus 240 for loose versus explicit bf16 attempts, and 487 versus 288 for nf4. Turns, tool calls and tool errors were nearly unchanged. Each group had one tool error in the same loose case, F5-07: `read_file("kb/")` returned “Is a directory”. Every set of 25 produced 25 final answers except the nf4 set containing F4-02, which encountered the harness's JSON error.

The analysis classified all 99 attempts that produced final answers, 49 nf4 and 50 bf16. `ASK` means asking about a choice, `SAY` means stating a default, `SILENT` means silently choosing one, and `IGNORE` means not addressing or producing the deliverable. There were seven ASK, three SAY, 89 SILENT and zero IGNORE results. Across all 40 non-F3 loose attempts, the model asked in 0/40, stated a default in 0/40 and silently chose in 40/40. Choices surfaced only in F3, where the brief itself asks what directions the writer could try. Quoted traces include the model considering and then declining to ask in bf16 F5-09 and nf4 F2-09 and F5-07.

## Compliance and the repeated-prompt control

The 120–220-word constraint was honoured in only 10/30 cases: 3/15 nf4 and 7/15 bf16. Violations were almost always overshoots. The F2 `local_revision` requirement to put tagged prose in the requested file was honoured in 1/6 cases; nf4 left the file untouched in all three. F4 KBs met the 500-word ceiling in 6/6 cases, and the distinction between draft-only suggestions and accepted revisions was honoured in 9/9 applicable cases.

The control repeated the explicit F1-01 prompt 25 times in each model format. All 25/25 bf16 outputs were within range, compared with 7/25 nf4 outputs. The analysis attributes part of the explicit-length violation to nf4 quantization, rather than entirely to brief specificity: the length requirement was held constant while the weight format changed.
