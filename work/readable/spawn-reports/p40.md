# Separate model failures from problems in the evaluation

Background agent p40 was asked to examine failures across 100 task attempts and distinguish weaknesses in the model from defects in the evaluation software or task requirements. It completed the analysis and verified a non-empty report; the results below explain what failed and which comparisons remain unavailable.

The `custom50` suite contains 50 writing tasks. An “attempt” is one run of a task. The two comparison groups, called arms in the source, use different model-weight formats: `nf4` is a 4-bit quantized format, and `bf16` is a 16-bit brain-floating-point format. Quantization stores weights at reduced precision. Explicit briefs state more requirements; loose briefs leave more creative choices open.

Task identifiers combine a family and a case number, as in F2-02. F1 asks for a reply scene; F2 asks for local revision or exploration followed by writing; F3 asks for alternatives; F4 asks for construction or updating of a knowledge base (KB), the project reference files; and F5 asks for writing using retrieved project facts.

## What the analysis established

There were 99 completed attempts and one error: F4-02 failed with a `ValueError` in the parser that interprets the model's tool-call format. The report counted 93/100 attempts with a deliverable. Seven prose attempts had no extractable `scene`, the output selected for scoring: 5/30 in nf4 and 2/30 in bf16. Completion and delivery are different counts; the underlying analysis includes files written before the F4-02 crash among the deliverables.

The bf16 group has 115 pending semantic checks and no ASTRA grading scorecards. Semantic checks judge meaning, rather than just file presence or word counts, so their outcomes cannot be compared between the two groups.

The report classified the following as model capabilities that training could address:

- Selected prose exceeded the word budget in 16/23 scored checks. The source gives nf4 as 9/15 and bf16 as 7/13; the underlying report explains that the nf4 denominator includes five unscored checks. Every scored length failure was an overshoot: 224–293 words against a ceiling of 220.
- Continuity, meaning consistency with supplied story facts, failed in 10/30 nf4 checks. The combined point-of-view and prose-style check, `pov-style`, failed in 9/15 nf4 checks.
- All 10/10 explicit F4 tasks across the two groups failed `wiki-links`, the check for links among KB pages.
- Retrieval failed to expose required evidence in 4/10 checks for established state and 5/10 for a character's belief. The `evidence_exposed` check looks for the required fact in a `read_file` or `search` result; writing from the brief without retrieving that fact does not pass it.
- F4 outputs omitted required facts. F2-02 failed `saved-scene`, which checks that the requested scene was saved. F3-02 failed `three-directions`, which checks the requested alternatives.

Several failures instead implicated the harness, meaning the software that runs and scores tasks, or its contract with the model:

- The `optional-context` judge rejected omissions its own prompt permits in 5/10 nf4 cases. The established-state check, `consequential-state`, had the same problem in F4-07.
- `pov-style` merges point of view and prose style into one result. All 9/9 failures passed the point-of-view part, so the combined label hides the actual style problem.
- `wiki-only` rejected a defensible help file outside `kb/` in 1/10 cases. The permitted edit locations were not adequately specified.
- In approximately 7/60 prose attempts, files left untouched could pass `saved-scene`, `preserve-ending` and `edit-scope`. These checks can accept a pre-existing file and its unchanged ending or edit boundary even when the requested writing was never done.
- F4-02 crashed while parsing the tool-call protocol.

## Evidence, output and verification

The agent read all 100 attempts: 49 nf4 `card.json` files, with one errored attempt; 50 bf16 `card.json` files; 50 nf4 ASTRA `scorecard.json` files; and `result.json` messages, tool traces and workspace files. It built a per-check pass/fail table, traced every failure to the judge's `rationale` and `evidence` and to the raw transcript or tool call, then classified it as a capability or harness/contract issue. Every classification has a counted denominator and a verbatim quotation from output, trace or judge evidence.

The nf4 point-of-view/style and continuity judgements are language-model assessments and therefore subjective; the report flags strictness in F1-06 and F1-09. The bf16 semantic outcomes remain unknown because they were not graded. Repeated-prompt distribution runs were outside this agent's scope.
