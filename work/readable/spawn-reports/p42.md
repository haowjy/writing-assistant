# Check whether the agent used project files and respected their facts

Background agent p42 was asked to audit tool use, the order of reading and writing, and failures to preserve established story facts across 100 attempts. It completed the analysis: every attempt offered tools used them, no writing attempt wrote before reading, and the report identified false save claims and continuity failures with quoted evidence.

The `custom50` suite contains 50 writing tasks. An “attempt” is one run of a task. The two comparison groups, called arms in the source, use different model-weight formats: `nf4` is a 4-bit quantized format, and `bf16` is a 16-bit brain-floating-point format. Quantization stores weights at reduced precision. Explicit briefs state more requirements; loose briefs leave more creative choices open.

Task identifiers combine a family and a case number, as in F2-02. F1 asks for a reply scene; F2 asks for local revision or exploration followed by writing; F3 asks for alternatives; F4 asks for construction or updating of a knowledge base (KB), the project reference files; and F5 asks for writing using retrieved project facts.

## Tool use and read-before-write behaviour

Tools were available in exactly 25/50 attempts in each group: F2, F4 and the five F5 `retrieved_kb` cases, where the knowledge base had to be retrieved with tools. In the other 25 per group, `visible.json["tools"]` was empty and there was no workspace. All 50/50 attempts offered tools called at least one.

There were 158 calls: 73 in nf4 and 85 in bf16. By tool, the totals were 69 `read_file`, 73 `write_file`, 11 `patch_file`, five `list_dir` and zero `search`. Two of 158 calls returned tool errors, one per group; both were F5-07 calls to `read_file("kb/")`, which attempted to read a directory as a file. One attempt, nf4 F4-02, aborted on malformed tool-call JSON and returned empty output.

The agent reconstructed ordering for each attempt. There were zero “cold writes”: 0/43 writing attempts wrote before doing any reading. Of the writes, 61 created new files. Of 23 writes to pre-existing files, ten followed a read of that same path and 13 addressed files the model had already created earlier in the attempt.

## Failures found in the transcripts

The nf4 F2-02 attempt claimed it had “saved to `drafts/scene.md`”, but its trace contained only a `read_file` call and the workspace had no saved scene. This false claim occurred in 1/100 attempts.

Ten of 30 nf4 continuity checks failed. The analysis puts each output beside the contradictory fact from `visible.json`, the KB or the source. Examples include F1-06's “like someone clearing his throat” against “heard their own voices”; F5-08's “They agreed that entering alone was dangerous” against “nobody agrees”; and F5-09 giving Pia the collector's key after reading `kb/canon.md`. Eight of ten failures occurred without tools; two occurred when tools were available.

For permission to change canon, meaning established story facts, 1/10 F4 `update` attempts failed. The bf16 F4-08 attempt replaced the committed fact “Noor … retaining her existing residence papers” with a draft-only suggestion without identifying it as a proposal. The other 9/10 respected the distinction or labelled the suggestion.

The original report describes tool-use behaviour across formats as “identical”. Its reported call totals differ, so this wording cannot mean identical counts. Its separate comparison found that loose briefs did not receive less reading: their mean call count was at least as high as explicit briefs in both groups. The raw 13-versus-12 split came from scenario assignment rather than a measured difference in willingness to read; the short report does not identify the exact quantity represented by that split.
